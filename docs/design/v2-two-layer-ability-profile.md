# V2 两层能力画像优化设计

## 1. 背景与问题

V1 直接把大模型生成的 `required_points` 作为画像主键。相同主题在不同题目中可能产生不同粒度、不同措辞的知识点，导致：

- 最近面试取得高分，但页面上原有主题分数不变化；
- 大量一次性细项被当成主画像，用户无法判断真实成长；
- 历史低分创建的复习任务不会被后续高分自动解决；
- 前端只能通过字符串合并细项，容易用最低子项分数掩盖主题进步。

本次优化不改变“面试 → 评分 → 画像 → 下一轮训练”的业务闭环，只修正画像的数据口径和状态推进规则。

## 2. 目标模型

采用两层模型：

### 2.1 稳定主题（主画像）

稳定主题是用户看到和训练排序使用的主能力，例如：

- RAG
- LangGraph
- Agent 工具调用
- 上下文与记忆管理
- AI Agent 工程化

每个主题维护独立的掌握度、可信样本权重、最近评分和版本号。主题分数只由可信评分渐进更新，不直接等同于某次面试百分比。

### 2.2 动态子知识点（诊断证据）

大模型输出的 `required_points` 不再直接成为主画像。系统先将其归并为主题下的稳定诊断维度，例如：

- RAG / 检索与召回
- RAG / 证据引用
- RAG / 生成边界
- LangGraph / 状态建模
- LangGraph / Checkpoint 与恢复

原始措辞保存在画像更新事件中，作为可审计证据；同义表述不会重复生成主画像。

## 3. 更新规则

### 3.1 可信评分门槛

- `disputed`、`review_pending`：不更新画像；
- `final` 且置信度小于 `0.70`：允许降权更新；
- `final` 且置信度大于等于 `0.70`：按完整权重更新。

### 3.2 渐进更新

沿用 V1 的指数平滑思想：

`新掌握度 = 当前掌握度 + (本次得分 - 当前掌握度) × 学习率`

学习率继续受置信度和题目难度影响。一次评分：

- 稳定主题只更新一次；
- 每个去重后的动态子知识点只更新一次；
- 不因一题包含多个 `required_points` 而重复放大主题得分。

### 3.3 复习任务解决

可信高分定义为：

- 评分状态允许更新；
- 置信度大于等于 `0.70`；
- 总分大于等于 `16 / 20`。

同一稳定主题（以及可匹配时的同一子知识点）的待复习任务按以下规则推进：

1. 第一次连续可信高分：`verification_streak = 1`，优先级降低一级；
2. 第二次连续可信高分：任务变为 `completed`；
3. 后续出现低分或错误：连续次数清零，任务恢复/保持 `open`，并重新计算优先级。

手工完成接口继续保留，但正常训练闭环不依赖手工点击。

## 4. 数据兼容策略

- 现有画像、错误和复习任务不删除，统一视为 `legacy` 记录；
- 新口径记录使用 `profile_level`、`topic_key`、`subtopic_key` 明确层级；
- API 默认只向当前页面返回 V2 两层画像，避免新旧口径混排；
- 画像更新事件记录 `hierarchy_version = 2`、原始知识点和归并结果，支持审计；
- 数据库迁移只增加字段和默认值，不覆盖原有评分、报告和画像历史。

## 5. API 与前端展示

画像 API 为能力和复习任务补充：

- `profile_level`
- `topic_key` / `topic_title`
- `subtopic_key` / `subtopic_title`
- `verification_streak`（复习任务）

前端展示规则：

- 主题卡片显示主题掌握度、样本权重、更新时间；
- 子知识点作为可展开诊断项，不再代替主题总分；
- 下一轮计划优先使用未完成的主题/子知识点复习任务；
- 连续验证进度显示为 `0/2`、`1/2`，完成后不再进入待复习列表。

## 6. 验收标准

1. 同一主题下不同措辞的 `required_points` 不再产生多个主画像；
2. 一次可信高分后，对应主题分数发生渐进变化；
3. 连续两次可信高分后，对应待复习任务自动完成；
4. 中间出现低分时，连续高分计数归零；
5. `disputed`、`review_pending` 不污染画像和验证计数；
6. 前端主卡片展示主题分数，子项仅作为诊断证据；
7. Alembic 可从 V1 数据库平滑升级，历史数据不丢失；
8. 单元测试、集成测试、Ruff、Pyright、前端构建和 Docker 运行态检查全部通过。
