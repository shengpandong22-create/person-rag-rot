# 题目数量与难度选择：影响评估（不开发 UI）

## 当前事实

后端 `POST /api/v1/interviews` 已允许 `question_count=1..10`，并接受 `easy / medium / hard`；
前端目前固定发送 `3` 和 `medium`。

这不是纯展示参数：每道完成且可信的评分都会进入画像更新。当前掌握度更新对难度使用不同
权重（easy 0.85、medium 1.0、hard 1.15），而多题面试会产生多次画像证据。因此直接开放
`1..10 × 三种难度`，会让训练时长和题目难度悄然改变画像的证据权重，造成不可比较的分数。

## 结论

本轮不开发选择器。默认三题中等难度仍是唯一可比的画像口径。

若将来要开放，必须先选定并验收以下一种规则：

1. **会话归一化（推荐）**：按会话聚合一次画像更新，或将每题证据权重按 `3 / question_count`
   归一化；需要新的回归集和历史兼容说明。
2. **练习模式隔离**：任意题数/难度只用于练习，不更新画像；实现较小，但用户需明确看到模式
   差异。
3. **固定档位**：仅开放 1、3、5 题，并为每档独立定义更新权重和展示口径；仍需实验验证。

在上述规则、回归测试和用户文案完成前，前端不应暗中把题数/难度当作无副作用控件。
