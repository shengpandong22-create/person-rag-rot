## 一、教案正文

### 6.1 先说结论

画像不是"展示几个百分比"，而是：

```
FINAL 评分（低置信 FINAL 降权）
    ↓
渐进更新两层画像：
  第一层：稳定主题（如 "RAG"、"Agent 工程"）→ 长期趋势
  第二层：动态诊断子知识点（如 "RRF融合"、"引用校验"）→ 具体薄弱点
    ↓
错误模式 → 复习任务（需两次连续验证才完成）
    ↓
训练焦点推荐 → 补缺（错误驱动）+ 查漏（知识覆盖缺口）
```

---

### 6.2 为什么旧画像会出现问题

如果直接把每道题的文本作为知识点，大模型每次换一种措辞就产生新节点：

```
"RAG 包含检索和生成两个阶段"     → 知识点 A
"RAG 检索增强生成"               → 知识点 B（和 A 是同一个东西！）
"检索阶段使用 Query 与 Key 匹配" → 知识点 C
```

最终界面出现大量重复碎片，无法回答"用户整体 RAG 能力如何变化"。

---

### 6.3 两层模型

#### 第一层：稳定主题

```
RAG
LangGraph
Agent 工程
Java 后端
```

用途：长期趋势跟踪、下一轮主题选择。数量少，不频繁变化。

#### 第二层：动态诊断子知识点

```
RAG
  ├── 混合检索与 RRF
  ├── 状态建模与恢复
  ├── 引用与证据边界
  └── 工具选择和参数校验
```

用途：解释具体薄弱点、错误模式、复习任务。随每次评分动态更新。

#### 分别解决什么问题

|                  | 第一层：稳定主题                   | 第二层：动态诊断子知识点                      |
| ---------------- | ---------------------------------- | --------------------------------------------- |
| **粒度**         | 粗（10-20 个）                     | 细（50-100+ 个）                              |
| **回答的问题**   | "用户 RAG 整体能力怎么样？"        | "RAG 里哪里是短板？是 RRF 融合还是引用校验？" |
| **用途**         | 长期趋势图、下一轮选什么主题       | 具体复习建议、错误模式诊断                    |
| **更新频率**     | 每次该主题下的评分都更新           | 每次涉及该子知识点的评分都更新                |
| **面试官看到**   | "RAG 掌握度从 0.40 → 0.47，在进步" | "薄弱点在 RRF 融合和检索策略，建议加强"       |
| **复习任务来源** | ❌ 不直接产生                       | ✅ 错误模式 → 复习任务                         |

核心思想：

> **稳定节点用于统计，动态证据用于诊断。主题回答"你整体怎么样"，子知识点回答"你哪里不行"。**

### 6.4 哪些评分允许更新画像

```python
# domain/profile.py

def profile_update_decision(status: str, confidence: float):
    if status in {EvaluationStatus.DISPUTED, EvaluationStatus.REVIEW_PENDING}:
        return ProfileUpdateDecision(
            should_update=False,
            reason=f"skip_{status}",
            confidence_weight=0,
        )
    if confidence < 0.70:
        return ProfileUpdateDecision(
            should_update=True,
            reason="low_confidence_final",
            confidence_weight=0.5,
        )
    return ProfileUpdateDecision(
        should_update=True,
        reason="trusted_final",
        confidence_weight=1.0,
    )
```

| 条件                       | should_update | confidence_weight | 含义               |
| -------------------------- | ------------- | ----------------- | ------------------ |
| disputed / review_pending  | ❌ False       | 0                 | 完全阻断           |
| final 且 confidence < 0.70 | ✅ True        | 0.5               | 允许更新，权重减半 |
| final 且 confidence ≥ 0.70 | ✅ True        | 1.0               | 完整权重           |

### 6.5 为什么高分后画像不会立刻满分——渐进更新

```python
def updated_mastery(current_mastery, score, *, confidence_weight, difficulty):
    difficulty_factor = {
        "easy": 0.85,
        "medium": 1.0,
        "hard": 1.15,
    }.get(difficulty, 1.0)
    learning_rate = min(0.35, 0.18 * confidence_weight * difficulty_factor)
    return round(
        current_mastery + (score - current_mastery) * learning_rate,
        4,
    )
```

#### 公式解读

```
新掌握度 = 旧掌握度 + (本次得分 - 旧掌握度) × 学习率

学习率 = min(0.35, 0.18 × confidence_weight × difficulty_factor)
```

#### 一个具体例子

```
当前 RAG 掌握度 = 0.40
本次得分 = 16/20 = 0.80
confidence_weight = 1.0（可信 final）
difficulty = "medium" → factor = 1.0
learning_rate = min(0.35, 0.18 × 1.0 × 1.0) = 0.18

新掌握度 = 0.40 + (0.80 - 0.40) × 0.18
         = 0.40 + 0.072
         = 0.472
```

一次高分（0.80）只能把画像从 0.40 拉到 0.472，而不是直接跳到 0.80。

#### 为什么设计成这样

| 设计目的                        | 防止的问题                             |
| ------------------------------- | -------------------------------------- |
| 一次高分不能覆盖全部历史        | 参考答案演示、偶然命题、运气好         |
| 学习率受 confidence_weight 影响 | 低置信评分影响力弱                     |
| 学习率受 difficulty 影响        | 简单题答对不加分太多，难题答对加分更多 |

### 6.6 ProfileService 如何应用评分

```python
# application/profile_service.py

decision = profile_update_decision(evaluation.status, evaluation.confidence)
topic = canonical_topic(interview_topic)
subtopics = canonical_subtopics(topic, question.knowledge_points, question_type)

if not decision.should_update:
    # 记录未应用的 ProfileUpdateEvent，然后返回
    return

for node in (topic, *subtopics):
    profile.mastery_score = updated_mastery(
        profile.mastery_score,
        normalized_score(evaluation.total),
        confidence_weight=decision.confidence_weight,
        difficulty=question.difficulty,
    )
```

关键细节：**同时更新主题和所有子知识点**。一次评分会同时影响"RAG"主题和"RRF融合"、"引用校验"等具体子知识点。

### 6.7 复习任务：为什么需要两次验证

```python
def review_verification_progress(current_streak, priority, *, trusted_high_score):
    if not trusted_high_score:
        return 0, priority, False          # 低分 → 重置
    next_streak = min(2, current_streak + 1)
    return next_streak, max(1, priority - 1), next_streak >= 2
```

#### 流程

```
第 1 次可信高分 → verification_streak = 1 → 任务保留，优先级降低
第 2 次连续可信高分 → verification_streak = 2 → 任务完成 ✅

中间低分或不可信结果 → 连续计数重置 → 回到起点
```

#### 为什么不是一次高分就完成

| 一次高分的问题                   | 两次验证的价值               |
| -------------------------------- | ---------------------------- |
| 可能恰好出了用户熟悉的题（运气） | 连续两次才能证明"确实掌握了" |
| 参考答案演示可能让用户照抄得高分 | 两次不同题目的高分更难作假   |
| 一次高分直接抹掉长期错误证据     | 需要持续证明才能消除错误记录 |

### 6.8 训练焦点如何排序

```python
# profile_service.py — recommend_interview_plan

推荐优先级：
  1. 复习任务（OPEN 状态，按 priority 降序）—— 补缺，错误驱动
  2. 知识覆盖缺口（uncovered/attempted/insufficient_evidence）—— 查漏
  3. 低掌握度稳定主题（mastery < 0.72）—— 巩固薄弱领域
  4. 后续维护或扩展训练

最终取前 5 条返回。
```

#### 覆盖缺口内部优先级

```python
for point in coverage.points:
    if point.status not in {"uncovered", "attempted", "insufficient_evidence"}:
        continue
    priority=3 if point.status == "uncovered" else 2
```

复习任务优先于查漏的逻辑：**已知的错误比未知的缺口更紧急。**

### 6.9 掌握度和覆盖度为什么必须分开

| 概念                   | 回答什么问题                   | 示例                          |
| ---------------------- | ------------------------------ | ----------------------------- |
| **掌握度**（画像）     | "用户回答过的题，表现怎么样？" | RAG 掌握度 0.47               |
| **覆盖度**（知识目录） | "知识库里的内容，被考到过吗？" | "多模态 RAG" 状态 = uncovered |

#### 覆盖度六种状态

```python
uncovered           → 资料里有，但没出过题
attempted           → 出过题，但还没有可信评分
insufficient_evidence → 只有一次可信验证，证据不足
verified            → 多次可信证据，表现中等
mastered            → ≥2 次可信验证，平均分达到阈值
weak                → 多次可信验证，但平均表现弱
```

#### 核心认知

> **未考到 ≠ 不会。未考到也不能默认已掌握。覆盖度独立于掌握度，分别回答不同问题。**

---

### 6.10 完整证据链

覆盖度不是靠"题目文本提到了某个名词"来判断的——它需要完整的证据链：

```
SourceDocument（原始文档）
  → KnowledgeChunk（分块 → KnowledgeCatalogSource 建立来源关系）
  → QuestionReference（题目引用了这个 Chunk）
  → QuestionCoveragePoint（题目 ↔ 知识点关联）
  → Evaluation（FINAL 评分；confidence ≥ 0.70 完整权重，低置信 FINAL 降权）
```

这条链路防止系统仅因为题目文本中出现了某个名词，就错误声称"已经考查了对应资料"。

---

### 6.11 数据流全景

```
Evaluation（FINAL, confidence=0.85）
    ↓
profile_update_decision → should_update=True, weight=1.0
    ↓
canonical_topic + canonical_subtopics → 提取主题和子知识点
    ↓
for each node: updated_mastery(旧分, 新分, weight, difficulty)
    ↓
写 AbilityProfile + ProfileUpdateEvent（审计记录：更新前后、为什么更新）
    ↓
classify_error → ErrorPattern（重复错误模式）
    ↓
task_priority → ReviewTask（待复习任务，需两次验证）
    ↓
rank_training_focuses → 训练焦点推荐（补缺 > 查漏 > 低掌握度）
```

## 二、学员疑问与讨论记录

### Q1：未覆盖的题目在之后会有什么推荐策略？是否会一直未被覆盖？

**分析路径：**

代码中 uncovered 以 priority=3 进入推荐列表（在覆盖缺口中最高，高于 attempted 的 priority=2）。但存在两个问题：

1. **被复习任务挤掉**：复习任务无上限追加，limit=5 时如果复习任务 ≥5 条，uncovered 全部被挤出
2. **依赖用户主动选择**：系统推荐但用户不选 → never attempted

**最小修改方案——预留查漏位：**

在 `recommend_interview_plan` 末尾加 ~10 行后处理逻辑：如果前 limit 条中没有 source_type="coverage_gap" 的项，把最后一条替换为优先级最高的覆盖缺口。

```python
# 新增逻辑（约 10 行）
top = recommendations[:limit]
has_coverage_gap = any(item.source_type == "coverage_gap" for item in top)
if not has_coverage_gap:
    coverage_candidates = [
        item for item in recommendations if item.source_type == "coverage_gap"
    ]
    if coverage_candidates:
        top = list(top)
        top[-1] = coverage_candidates[0]
    recommendations = top + recommendations[limit:]
```

改动量：~10 行，不改数据库、不改 API、不改前端。后续可叠加"积压老化"——uncovered 时间越长 priority 自动提升。
