# 连续覆盖训练证据验收契约 v1

## 目的与边界

此契约验证已经上线的“选择 coverage gap → 生成题目 → 引用目标来源 → 记录覆盖”的连续训练路径。它不评估答案正确性、画像提升或知识掌握，也不修改真实知识库。

## 固定输入

- 夹具：`evals/fixtures/continuous-coverage-training-v1.md`
- 六个目标：RRF 公式、引用白名单、checkpoint 恢复、幂等提交、Rubric 重算、低置信复核路由
- 每个目标恰好创建一个 `question_count=1` 的独立面试会话。
- 每次均显式提交对应 `coverage_catalog_point_id`；不允许按 case id、模型输出或标签改选目标。

## 执行协议

1. 运行前读取 `/health/runtime` 并写入 provider/model。
2. 创建全新、隔离的知识库并上传固定夹具，等待入库完成。
3. 按固定顺序执行六个会话；真实模型开启时保留每个问题原文、生成模式、延迟和引用 chunk id。
4. 运行结束后读取 coverage 快照。运行器不得提交答案、生成报告、更新画像或写入任何已有知识库。
5. 运行器至少六次真实题目生成；一次运行不构成连续覆盖结论。

## 硬门槛

- 6/6 问题均为 `generation.mode=llm`（若 runtime 明示 LLM 可用）。
- 6/6 问题至少引用一个对应 catalog point 的 source chunk。
- 覆盖快照中 6 个目标均有至少一次尝试记录。
- 本次运行的唯一目标数为 6，重复目标数为 0。
- 任何 API、入库或引用校验失败即整体不通过；不针对该夹具修改算法后重跑。

## 解释红线

通过仅说明“连续训练选择与证据记录链路”可用；不说明用户已经掌握这些知识点。只有可信评分满足既有阈值时，产品才会将 attempted 进一步显示为 verified。
