# ADR-003：阶段性关闭二阶段检索生产接入

- 状态：Accepted
- 日期：2026-10-05
- 分支：`codex/eval-foundation-rebuild`
- 结论：保留安全基础设施和 eval-only 候选，不接 Evidence Gate、生成、API 路由或前端，不授权生产开启。

## 背景

本实验线希望在完全保留首次检索 Top-6 的前提下，通过 heading-shadow 补充少量章节证据。实施过程中坚持单调安全、默认关闭和先实验后接入：先定义 API/trace/预算，再实现持久化与纯预算器，最后才评估候选召回和消费策略。

## 已验证能力

- `ChatRetrievalExpansionModel`、SQLAlchemy repository 和幂等 claim 骨架已经实现；feature flag 默认关闭。
- 原 Top-6 的对象与顺序保持率为 100%。
- supplemental/combined 的 7/13/7000/18000 预算和 exact chunk 去重均通过单元测试。
- `primary-context-dedupe-v1` 修正了 supplemental 错误排除 vector Top-20 尾部证据的问题。
- 非盲 Development 中 Combined Recall 从 0.50 提升到 1.00，6/6 primary miss 被补回。
- regression 安全验证中30/30样本的 Primary Top-6 完全一致；Primary Recall 保持0.55，Combined Recall 为0.70；Gate 与生成调用均为0。
- supplemental 额外检索 P95 约100ms，字符预算有充足余量。

## 未解决问题

- regression 固定消费精度只有0.019，10个负例产生185个 supplemental candidates。
- `rank-capped-3-v1` 虽保持 Development Recall 1.00，并将消费量降低约57%，但综合消费精度只有0.2353，未达到预声明的0.30。
- heading 路径新颖性、同文档新章节、文档分歧、问题—heading 词面覆盖和概念重复度均无法区分可补回正例与困难负例。
- 困难负例通常命中正确主题，但请求资料中不存在的数值、SLA、绝对保证或零错误结论；纯检索结构信号无法判断这些声明是否得到证据支持。

## 决策

1. 保留 repository、orchestration skeleton、预算器、eval-only provider、`primary-context-dedupe-v1`、runner 和全部真实报告。
2. `AGENT_MENTOR_RETRIEVAL_EXPANSION_ENABLED` 继续默认 `false`。
3. 不注册扩展检索 API 路由，不接 AnswerService/Evidence Gate/LLM，不实现前端按钮。
4. 不降低已失败的消费精度门槛，不继续扫描 1/2/3 个 chunk、heading score 或 RRF 阈值。
5. 不运行 validation 或 holdout，不以 regression 诊断结果继续调参。
6. 把“缺少可靠的 demand-to-evidence support 信号”记录为已知限制，而不是用未经证明的规则隐藏它。

## 为什么这仍是有效工程成果

实验不仅证明 heading supplemental 能补回证据，也定位了它不能安全进入回答链路的原因。候选必须先通过数据、门槛和安全协议，失败结论被保留而不是覆盖。该链路展示了可复现评测、单变量消融、幂等并发、单调上下文预算、标签隔离和生产授权边界，形成了完整的工程闭环。

## 重新开启条件

只有同时满足以下条件，才重新讨论生产接入：

- 在新的非盲 Development 上存在标签无关的 support-presence 信号，能识别数值、单位、关系和保证性需求；
- 该信号保留已观察到的增量召回，同时显著降低困难负例消费；
- 候选先通过新的 regression 协议，再预声明 validation 协议；
- validation 通过后另建独立验收集，冻结数据、门槛和 single-run protocol；
- 生产接入另行设计 feature flag、回退、监控、引用白名单和集成测试。

在这些条件满足前，本实验线视为阶段性完成，不继续扩大范围。
