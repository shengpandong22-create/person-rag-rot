## 9. 第 1 批训练质量修复：题目角度轮换

### 9.1 发现的问题

50 轮验收中，系统没有出现流程中断，但暴露出一个训练质量问题：题面文本虽然不完全相同，但部分题目在语义上仍然偏重复。例如同一主题下容易反复追问“RAG 是什么、如何落地、如何保证可靠性”，用户连续训练时会感觉是在回答相似题。

这说明系统已经从“流程是否能跑通”的阶段，进入了“训练是否足够有效”的阶段。此时继续只看成功率、总分和画像更新是不够的，还要关注题目是否能从不同角度检查用户能力。

### 9.2 原因定位

原有出题策略主要由三类信息驱动：

1. 用户选择的主题；
2. 当前题型：概念题、场景题、设计复盘题；
3. 检索召回的资料片段和覆盖盲区。

这能保证题目贴合知识库和画像补缺，但还缺少一个独立维度：本题到底要考察哪个面试角度。因此在同一主题、同一批资料、相近检索片段下，大模型容易生成“表述不同但考察意图相似”的题。

### 9.3 最小改造方案

本次没有新增表结构，也没有改动主流程，而是在 `InterviewService` 内加入题目考察角度轮换：

- 概念边界：定义、边界、易混淆概念；
- 架构取舍：组件职责、数据流、替代方案；
- 异常与降级：失败场景、重试、幂等、风险控制；
- 生产化与观测：日志、指标、Trace、评估集；
- 对比辨析：相似方案差异、优缺点、选择理由；
- 质量评估：验收指标、评测方法、质量提升判断。

代码路线：

- `src/agent_mentor/application/interview_service.py`
  - 新增 `QuestionAngle`；
  - 新增 `QUESTION_ANGLES`；
  - `_question_angle()` 根据面试 ID 和题号做轮换；
  - `_question_search_text()` 将角度关键词加入检索查询；
  - `_question_prompt()` 明确告诉 LLM 本题必须体现考察角度；
  - `rubric.question_angle` 记录本题角度，便于后续前端展示、审计和问题追踪。

### 9.4 预期收益

这次改造的价值不在于“随机换题”，而在于把出题从单一主题驱动升级为：

`主题 + 知识库检索片段 + 覆盖盲区 + 考察角度`

这样同一个主题可以被拆成不同训练目标。例如 RAG 不再只问“RAG 是什么”，而可以分别追问：

- RAG 和普通 LLM 问答的边界是什么；
- 生产环境下如何做检索降级；
- 如何验证召回质量；
- 为什么选择向量检索而不是全文检索；
- 引用白名单如何影响评分可信度。

### 9.5 验收方式

本次先补充单元测试验证改造不破坏原流程：

- `test_question_angle_rotates_by_interview_and_sequence`：验证同一场面试内题目角度会轮换；
- `test_question_search_text_includes_coverage_focus_when_present`：验证覆盖盲区和角度关键词都会进入检索查询；
- `test_deterministic_question_text_exposes_angle`：验证 LLM 降级出题也会体现考察角度。

后续如果继续做训练质量评估，可以在审计脚本中统计每轮题目的 `rubric.question_angle.key` 分布，判断 50 轮面试是否真正覆盖不同考察角度。
