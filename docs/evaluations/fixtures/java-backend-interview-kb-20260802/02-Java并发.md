# Java 并发与内存模型

## Happens-before

Happens-before 描述跨线程操作的可见性与顺序保证。监视器解锁先于随后对同一监视器的加锁；对 volatile 字段的写先于随后对该字段的读；调用 `Thread.start()` 先于新线程中的动作；线程内动作先于其他线程从 `join()` 成功返回后的动作。

`volatile` 提供可见性和特定排序保证，但不提供复合操作的互斥原子性。`count++` 包含读、修改、写，多个线程仍可能丢失更新。需要根据场景使用锁、原子类或并发容器。

线程池必须显式考虑核心线程数、最大线程数、队列、拒绝策略、任务超时与上下文传播。无界队列可能隐藏过载直到内存耗尽；盲目扩大线程数可能增加调度和下游竞争。

### 面试题：volatile 能否保证线程安全？

参考答案要点：先区分可见性、排序与原子性；单次 volatile 读写具有保证，但依赖旧值的复合更新不安全；给出状态标志与计数器两个对比例子。

### 面试题：如何设计生产线程池？

参考答案要点：根据 CPU/IO 特征和下游容量估算；使用有界队列、命名线程、拒绝与降级策略；监控活跃数、排队、拒绝、耗时；请求取消时正确处理中断。
