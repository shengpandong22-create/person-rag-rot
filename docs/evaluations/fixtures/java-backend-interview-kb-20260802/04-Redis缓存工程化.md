# Redis 缓存工程化

这份增量资料用于验证：向已有知识库新增文档后，系统应增加“待覆盖”知识点，但不应降低此前已经形成的 Java 能力画像。

## Cache-Aside 一致性模式

Cache-Aside 由应用负责缓存读写。读取时先查缓存，未命中再查数据库并回填；写入时通常先更新数据库，再删除缓存。删除失败需要通过重试、消息队列或订阅数据库变更日志补偿。该方案追求最终一致性，而不是宣称缓存与数据库始终强一致。

## 缓存穿透与空值治理

缓存穿透是查询不存在的数据导致请求持续访问数据库。可采用参数校验、短期缓存空值和布隆过滤器组合治理。布隆过滤器存在误判，不能把“可能存在”当作数据一定存在，并且需要考虑数据新增时的同步更新。

## 缓存击穿与热点互斥

缓存击穿发生在热点 Key 失效瞬间，大量并发请求同时回源。常见方案包括互斥重建、逻辑过期和热点数据提前续期。互斥锁必须设置租约与超时，并在获取锁失败时采用退避或读取旧值，避免把缓存问题转化为线程堆积。

## 缓存雪崩与多层保护

缓存雪崩是大量 Key 同时失效或缓存服务整体不可用，导致流量集中回源。可以通过过期时间抖动、多级缓存、限流熔断、服务降级、Redis 高可用和数据库保护共同治理。工程上应监控命中率、回源量、热 Key、延迟与错误率，并进行故障演练。
