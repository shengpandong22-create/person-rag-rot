# Agent 生产工程面试资料

## 核心知识

生产 Agent 的核心挑战是不确定模型与确定业务系统之间的边界治理。应用层需要负责状态机、权限、事务、幂等、预算和最终业务计算，模型负责受约束的语义判断与生成。

可观测性至少关联 request、user、thread、model call、tool call、retrieval 和 checkpoint，记录模型与 Prompt 版本、Token、延迟、成本、错误、降级原因和关键状态迁移。日志要脱敏，Trace 不能泄露密钥和隐私。

安全上要把用户输入、检索文档和工具结果都视作不可信数据。系统指令与数据隔离，工具最小权限，敏感操作人工审批；租户隔离同时覆盖关系数据、向量索引、缓存、对象存储与日志。

部署应支持超时、并发控制、限流、熔断、重试退避、健康检查和优雅降级。资源受限环境中可把数据库、API、前端容器化，外部调用大模型，限制连接池和 Worker，并用真实运行指标证明资源约束。

## 常见面试题

### 1. Agent 系统中哪些逻辑不能交给模型？

参考答案要点：权限、金额、最终评分、状态迁移合法性、幂等和事务等必须由确定性应用层控制；模型输出只作为候选结构化建议并需校验。

### 2. 如何设计端到端可观测性？

参考答案要点：统一关联 ID，记录检索、模型、工具和工作流事件；建立延迟、成本、失败与质量指标；支持从最终报告反查证据、Prompt 和版本。

### 3. 如何应对模型或外部工具故障？

参考答案要点：明确超时、有限重试、熔断、备用模型或确定性降级；持久化状态以便恢复；区分可重试与不可重试错误，避免重放副作用。

### 4. 从个人项目扩展为企业系统需要什么？

参考答案要点：身份与租户隔离、RBAC、数据权限过滤、复杂文档解析、异步任务、对象存储、可观测平台、评测门禁、合规审计、容量与灾备；按风险分阶段演进，不直接宣称当前版本已具备。
