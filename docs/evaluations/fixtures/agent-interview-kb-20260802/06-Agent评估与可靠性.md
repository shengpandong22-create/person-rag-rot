# Agent 评估与可靠性面试资料

## 核心知识

Agent 评估不能只看最终答案，因为同一结果可能来自不同轨迹，失败也可能发生在工具选择、参数、检索、状态迁移或终止判断。评测应同时覆盖最终结果、关键过程和系统指标。

建立评测集时先定义任务分布和失败分类，再收集正常、边界和对抗样本。确定性规则优先验证 Schema、权限、引用和状态；语义质量可使用人工 Rubric 或 LLM-as-Judge，但模型裁判需要校准、盲测、重复性检查和人工抽检。

离线评测适合版本回归，在线观测用于发现真实分布变化。每次模型、Prompt、检索器、工具或数据版本变化都应可追踪。发布门禁不只看平均分，还应关注关键失败率、长尾任务、P95 延迟、成本和降级比例。

## 常见面试题

### 1. 如何建立 Agent Eval 体系？

参考答案要点：从业务成功标准与失败分类出发，构建版本化数据集；分别评估结果、轨迹和系统性能；自动规则、模型裁判与人工审核组合；接入 CI 回归和线上抽样。

追问：数据集如何避免过拟合？线上问题如何回流？

### 2. LLM-as-Judge 有什么风险？

参考答案要点：位置、长度、自偏好和提示敏感性；通过清晰 Rubric、隐藏候选身份、交换顺序、多次评审、参考答案、人工校准和争议路由降低风险。

### 3. 平均分提高是否代表版本更好？

参考答案要点：不一定，可能牺牲关键场景或安全边界。需按任务类别分层，观察失败分布、置信区间、回归样本和业务代价。

### 4. LLM 不可用时如何降级？

参考答案要点：区分核心路径与增强路径；使用确定性规则、缓存或模板返回，标注生成模式和置信度，避免降级结果污染长期画像。
