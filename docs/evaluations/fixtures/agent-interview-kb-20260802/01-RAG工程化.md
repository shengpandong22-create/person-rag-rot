# RAG 工程化面试资料

## 核心知识

RAG 将知识检索与模型生成解耦：摄入阶段解析、清洗、切分、去重、向量化并保存来源元数据；查询阶段进行查询理解、候选召回、融合或重排、证据过滤，再把有限且可追踪的证据交给模型生成。RAG 提升的是基于外部证据回答的可控性，不保证天然正确。

复杂文档不能只做定长切分。应识别标题层级、表格、列表、页码和跨页关系，保存父子块、标题路径和原文定位。检索可结合向量召回与全文检索；RRF 用排名而非原始分数融合不同检索器，适合量纲不一致的候选列表。

知识边界必须在生成前后共同控制：检索分数、有效证据数量和来源可信度不足时拒答或提示补充资料；生成后校验引用只指向本次召回白名单，并检查回答中的关键主张能否被证据支持。

## 常见面试题

### 1. 如何设计一条可落地的 RAG 链路？

参考答案要点：说明离线摄入与在线查询两条链路；覆盖解析、结构化切分、去重、Embedding、索引、查询改写、混合召回、重排、证据门控、带引用生成和评估；说明每阶段的日志、版本与失败恢复。

追问：为什么不能只依赖向量相似度？切分参数如何评估？索引更新时怎样避免新旧数据混用？

### 2. 如何降低 RAG 幻觉？

参考答案要点：提高证据质量只是第一步，还需设置证据门槛、限定上下文、提示模型只依据证据、输出引用、执行引用白名单和忠实度评估；证据不足显式降级。

追问：检索到了错误资料怎么办？模型给出正确答案但引用不支持，应判定为成功吗？

### 3. 企业复杂文档的难点是什么？

参考答案要点：版面解析、表格与图片、多级标题、扫描 OCR、版本权限、增量更新、跨块语义和可追溯性。解决方案是解析器路由、结构化中间表示、父子块检索、元数据过滤、质量抽检和解析失败队列。

### 4. 如何评估 RAG？

参考答案要点：分别评估检索和生成。检索看 Recall@K、MRR、nDCG、命中来源；生成看正确性、忠实度、引用准确率、拒答准确率；同时记录延迟、Token、成本和失败率。

## 易错边界

- 相似度高不等于事实正确。
- 引用存在不等于引用支持主张。
- 增大 Top-K 可能增加噪声并恶化生成。
- RAG 与微调解决的问题不同：前者注入可更新知识，后者更适合行为与风格适配。
