# LangChain Agent 面试资料

## 核心知识

Agent 的本质是模型在循环中根据当前上下文决定是否调用工具、读取工具结果并继续推理，直到生成最终答案或触发停止条件。LangChain 提供模型、工具、中间件、结构化输出等抽象；`create_agent` 构造的运行时建立在 LangGraph 之上，因此生产级持久化、中断和恢复仍需理解底层状态图语义。

工具描述和参数 Schema 是模型决策的一部分。Schema 应最小、明确、可验证；工具返回值应区分业务失败与系统失败。结构化输出可由模型原生能力或工具调用策略实现，应用层仍需做 Schema 校验和失败重试。

中间件适合处理横切关注点，例如模型路由、动态提示词、敏感信息处理、调用限流、工具错误转换和可观测性。不能把核心业务状态隐藏在不可追踪的 Prompt 拼接里。

## 常见面试题

### 1. Agent 与普通 LLM 调用有什么区别？

参考答案要点：普通调用通常是单次输入输出；Agent 包含决策—行动—观察循环，可动态选择工具并维护状态。代价是延迟、成本、不确定性和安全面增加，因此需要预算、终止条件和观测。

追问：什么场景不应该使用 Agent？如何防止无限循环？

### 2. 如何设计可靠的工具 Schema？

参考答案要点：名称语义明确、参数最少、类型和枚举严格、描述包含使用边界；服务端再次校验参数，设置超时、幂等键和权限；返回结构化结果并区分可重试错误。

### 3. 中间件适合解决什么问题？

参考答案要点：处理跨模型和工具调用的统一策略，不承载领域真相。举例说明动态模型选择、Prompt 注入、审计、重试与 PII 处理，并强调顺序和副作用。

### 4. 结构化输出失败怎么办？

参考答案要点：先选择原生 Schema 或工具策略；解析失败时有限重试、缩小 Schema、记录原始输出；最终走确定性降级，不能把非法 JSON 当作可信业务对象。
