# 上下文与 Memory 面试资料

## 核心知识

上下文是一次模型调用实际可见的信息，包含系统指令、消息、检索证据、工具结果和运行时元数据。Memory 是跨步骤或跨会话保存并在需要时重新注入上下文的信息机制。两者不能混为“保存全部聊天记录”。

短期记忆通常绑定 thread，用于保持当前任务状态；长期记忆跨 thread 保存用户偏好、事实或经验。写入长期记忆前要明确数据类型、来源、置信度、过期时间和用户隔离，读取时按相关性与权限选择，而非全部注入。

上下文窗口有限时，可采用裁剪、摘要、结构化状态、检索式记忆和分层压缩。摘要会丢失细节，必须保存原始来源或可追溯引用；压缩策略需通过任务成功率、事实保留率、成本和延迟验证。

## 常见面试题

### 1. 短期记忆和长期记忆如何划分？

参考答案要点：短期记忆服务当前 thread 的连续决策；长期记忆跨会话复用。说明生命周期、隔离键、存储和召回策略，不以数据库表的位置作为概念定义。

### 2. 为什么不能把全部历史消息放入上下文？

参考答案要点：受 Token、成本、延迟和注意力稀释影响；历史中还可能有过期事实和 Prompt Injection。应按任务选择、压缩和检索。

### 3. 如何防止错误记忆长期污染？

参考答案要点：记录来源与置信度、区分用户声明和模型推断、需要确认的写入走审批、支持版本和删除、定期衰减或重新验证。

### 4. 用户画像是不是 Memory？

参考答案要点：画像可视为一种结构化长期记忆，但它应由可信事件渐进更新，具有知识库和用户作用域，不应直接保存模型生成的任意结论。
