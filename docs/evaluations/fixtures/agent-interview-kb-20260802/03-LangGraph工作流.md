# LangGraph 工作流面试资料

## 核心知识

LangGraph 用显式 State、Node 和 Edge 表达长流程。State 是节点共享的数据契约；Reducer 决定并发或多次更新如何合并；条件边根据状态选择下一节点。图适合需要可恢复、可观察和人工介入的 Agent 流程，而不是把所有逻辑都塞进一个节点。

Checkpoint 把某个 thread 的状态快照持久化，使流程可以读取历史状态、故障后继续或从指定位置恢复。`thread_id` 是状态隔离和恢复的关键标识，不等同于业务用户 ID。生产环境需要持久化 Checkpointer，并考虑序列化、并发写入、版本升级和保留策略。

Interrupt 会暂停图并返回需要外部处理的数据。恢复时以同一 thread 和 resume 命令继续；中断前的副作用必须幂等，因为节点可能重放。流式输出可发送状态更新、消息或自定义事件，前端应按事件类型恢复 UI，而非把连接断开直接视为任务失败。

## 常见面试题

### 1. 为什么使用状态图而不是普通函数链？

参考答案要点：状态图把分支、循环、暂停、恢复和状态迁移显式化，便于观测与测试；简单顺序流程使用函数链更轻量，需根据复杂度选择。

### 2. Checkpoint 能解决什么，不能解决什么？

参考答案要点：解决状态持久化、历史读取和恢复；不能自动保证外部 API、数据库写入等副作用只执行一次，仍需幂等键、事务和补偿。

追问：节点在写数据库后崩溃会怎样？如何设计恢复测试？

### 3. Interrupt 如何支持 Human-in-the-loop？

参考答案要点：节点抛出中断并保存状态，外部审核后以相同 thread 恢复；审核数据要校验，暂停状态要可查询，超时需有策略。

### 4. 如何升级正在运行的图？

参考答案要点：状态 Schema 版本化、迁移旧 Checkpoint、保证节点兼容、灰度切流；不能假定代码更新后旧状态天然兼容。
